## Context

See `proposal.md` for motivation. Current `develop` now includes PR #437, which separates a 20,000-entry ordinary-content allowance from a 100,000-entry generated-content allowance and retains complete nested-repository, link, special-file, cancellation, and deadline checks. That base change resolves the retained PR #435 dependency-tree blocker. The remaining PR #438 blocker is a small ignored Cargo tree at `native/process-guardian/target` that is structurally ordinary but not centrally authorized.

## Goals / Non-Goals

**Goals:**
- Preserve the deployed dual-budget inspection implementation unchanged.
- Authorize only the two native Cargo roots generated by repository build commands.
- Prove both exact roots complete normally and arbitrary `target` paths remain blocked.
- Keep the state schema aligned with the central policy without admitting wildcard roots.

**Non-Goals:**
- Reimplementing or widening PR #437's generated-content allowance.
- Authorizing every directory named `target`, the whole `native` tree, or recursive glob policies.
- Deleting PR #435 or PR #438 worktrees before this change is merged and verified.

## Decisions

### Reuse the deployed generated-content allowance

Native roots enter the same exact disposable list consumed by the existing generated-path classifier. No traversal code or resource limit changes are required: descendants of an approved native root count against the 100,000-entry generated allowance, while ordinary source content retains its separate 20,000-entry allowance.

Alternative considered: retain this branch's earlier single 100,000-entry whole-worktree implementation and oversized physical fixture. Rejected because current `develop` already provides stronger separation, and the duplicate fixture exceeded the existing hosted resource-test timeout.

### Add two exact native Cargo roots

Add `native/process-guardian/target` and `native/terminal-host/target` to the immutable completion policy and exact registration schema. Both are root-anchored ignored outputs of repository-owned native builds. Existing component-boundary matching permits descendants without matching `target`, `native/other/target`, or near-match names.

Alternative considered: authorize `native/*/target`. Rejected because wildcard policy would grant future or user-created native projects cleanup authority without review.

### Exercise ordinary completion and exact negative boundaries

Disposable repositories will create representative output under each approved root and invoke the standard completion path through non-force worktree/ref removal. Separate fixtures for root-level `target`, sibling native-project output, and a near match must report `worktree-content`. Existing generated-allowance and unsafe-content tests remain unchanged as regression coverage.

## Risks / Trade-offs

- [Approved Cargo output contains unsafe structure] → Full generated-root traversal still rejects nested repositories, links, special files, and allowance/deadline exhaustion.
- [A future native project needs cleanup] → Add another exact root through review rather than widening to a glob.
- [State schema and completion defaults drift] → Pin both accepted exact roots and rejected generic/sibling forms in focused tests.

## Migration Plan

1. Merge and verify this change through the normal version-3 workflow.
2. Update primary `develop` so the exact native roots are deployed alongside PR #437's dual budgets.
3. Retry the exact `complete` command for retained PR #435, then retained PR #438.
4. Run this change's own exact completion command after its authorized merge and verification.

Rollback is an ordinary corrective PR removing the native roots. Retained candidates continue to fail closed; already removed worktrees remain recoverable from merged Git history.
