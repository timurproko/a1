## Context

See `proposal.md` for motivation. Cleanup performs a complete directory walk after Git status classification so it can reject nested `.git` metadata, symbolic links, junction-like entries, and special files even inside ignored disposable roots. The current walk stops after 20,000 visited entries. A standard installed dependency tree currently contains about 20,062 entries before recursive-directory accounting, while the full retained PR #435 worktree contains about 24,046 filesystem entries. PR #438 also contains a small ignored Cargo build tree at `native/process-guardian/target` that is structurally safe but not centrally authorized.

## Goals / Non-Goals

**Goals:**
- Preserve complete structural traversal while accommodating the repository's normal dependency footprint.
- Keep entry-count and wall-clock safeguards finite and fail closed.
- Authorize only the two native Cargo roots generated by repository build commands.
- Prove the former limit, new limit, native roots, and exact-path boundaries in disposable repositories.

**Non-Goals:**
- Skipping traversal for `node_modules` or any other disposable root.
- Authorizing every directory named `target`, the whole `native` tree, or recursive glob policies.
- Dynamically sizing authority from the retained live worktrees.
- Deleting PR #435 or PR #438 worktrees before this change is merged and verified.

## Decisions

### Raise the finite entry ceiling to 100,000

Replace the embedded 20,000 value with a named 100,000-entry production ceiling used for both directory and child accounting. This is more than three times the currently observed full-worktree traversal cost while remaining finite and subordinate to the existing 60-second pass deadline and cancellation checks. Export or inject the limit only as needed for focused tests; callers cannot disable it or request infinity through the CLI.

Alternative considered: exempt regular files inside approved roots from counting or traversal. Rejected because a generated tree can contain nested Git metadata, links, or special files at any depth, and incomplete traversal must not grant deletion authority.

Alternative considered: remove the entry ceiling and rely only on time. Rejected because deterministic resource bounds are part of the cleanup contract.

### Add two exact native Cargo roots

Add `native/process-guardian/target` and `native/terminal-host/target` to the immutable completion policy. Both are root-anchored ignored outputs of repository-owned native builds. Existing component-boundary matching permits descendants without matching `target`, `native/other/target`, or near-match names.

Alternative considered: authorize `native/*/target`. Rejected because wildcard policy would grant future or user-created native projects cleanup authority without review.

### Test the old threshold and configurable failure boundary separately

A disposable fixture will create structurally safe ignored content above 20,000 entries and verify the production ceiling permits normal non-force removal. Smaller fixtures with an injected low entry ceiling and deadline will verify fail-closed budget behavior without requiring a second oversized tree. Native-root positive fixtures and arbitrary-target negative fixtures pin exact matching. Existing link, special-file, nested-repository, identity, journal, and idempotency assertions remain unchanged.

## Risks / Trade-offs

- [Larger traversal consumes more time or memory] → Stream directory entries with the existing recursive walk, retain the 60-second deadline/cancellation checks, and cap visits at 100,000.
- [Repository dependencies grow beyond 100,000 entries] → Fail closed with `content-inspection-budget`; adjust through another reviewed change with measured evidence rather than automatic widening.
- [Approved Cargo output contains unsafe structure] → Full traversal still rejects nested repositories, links, and special files.
- [Large fixture increases focused-test latency] → Generate minimal empty entries in one ignored approved directory and retain a separate low-limit fixture for the blocker path.

## Migration Plan

1. Merge and verify this change through the normal version-3 workflow.
2. Update primary `develop` so the revised inspector and exact native roots are deployed.
3. Retry the exact `complete` command for retained PR #435, then retained PR #438.
4. Run this change's own exact completion command after its authorized merge and verification.

Rollback is an ordinary corrective PR restoring the lower ceiling and removing the native roots. Retained candidates continue to fail closed; already removed worktrees remain recoverable from merged Git history.
