## ADDED Requirements

### Requirement: Every presented Pi setting has a reviewed effect and a generated presentation inventory
The reviewed effect table for Pi settings SHALL map every key A1 knows to its application timing, active owner, visual class, and observable effect. Automated conformance SHALL fail when a presented key has only metadata, a storage setter, or a selector callback without a tested effect, and when an unavailable key appears as a disabled explanatory row. The presentation inventory (presented keys, order, wording, dialog parts, and bounds) SHALL be generated from the pinned engine's own source at build time into the shipped tree rather than committed, and one settings bridge SHALL carry both the engine settings port and the reviewed effect table.

#### Scenario: Add or expose a Pi setting
- **WHEN** the pinned Pi inventory gains a setting or A1 begins presenting one
- **THEN** conformance SHALL fail until its application contract, owner, effect test, capability predicate, and visible-or-hidden behavior are recorded

#### Scenario: Disconnect an existing effect
- **WHEN** a writable setting continues to persist but no longer changes its declared owner or observable output
- **THEN** behavioral conformance SHALL fail

#### Scenario: Presentation metadata is regenerated by the build
- **WHEN** the package is built or the test run starts
- **THEN** the presentation inventory SHALL be extracted from the pinned engine and written beside the settings bridge, and no committed copy SHALL exist for it to drift from

## MODIFIED Requirements

### Requirement: Normal A1 exit hints round-trip through the public command
A resume hint emitted by the normal A1 profile SHALL be accepted by that build's installed public CLI and restore the exact persisted session using that build's pinned Pi behavior when run from the original project with its session store available. Default-directory hints SHALL retain compact session IDs without raw default file paths. Custom-directory hints SHALL retain correctly quoted `--session-dir` before `--session`. Bare A1's hint-only exit and the comparison profile's `transcript` and `resume-hint` modes SHALL share this executable behavior, preserve existing terminal-restoration ordering and styling, and SHALL NOT claim resumability for an unpersisted session.

#### Scenario: Execute a default-directory hint
- **WHEN** a newly created normal A1 session persists conversation messages in default storage, exits, and the user copies its hint into the original project shell
- **THEN** the public command SHALL restore the same session identity and persisted conversation rather than silently exit or launch an empty session

#### Scenario: Execute a custom-directory hint
- **WHEN** a normal A1 session exits with custom storage whose path needs shell quoting and the user executes the hint
- **THEN** the public command SHALL preserve the directory argument and restore the exact session ID

#### Scenario: Compare exit modes
- **WHEN** the same persisted session exits from bare A1 and from the comparison profile using `transcript` or `resume-hint`
- **THEN** every emitted command SHALL select the same session without changing the declared output style or terminal cleanup behavior

#### Scenario: Session was never persisted
- **WHEN** the normal A1 UI exits without a persisted resumable session
- **THEN** it SHALL NOT emit a command claiming that session can be resumed

## REMOVED Requirements

### Requirement: Behavioral conformance covers every exposed Pi setting
**Reason**: The text and three scenarios prescribed acceptance evidence: independent parity fixtures, their normalization rules, and physical-terminal acceptance.
**Migration**: The product rules are kept by "Every presented Pi setting has a reviewed effect and a generated presentation inventory"; acceptance evidence is owned by the shared delivery workflow.
