# Design

## Absent registered worktree at step `none`

`completeLocalCleanup` finds the released entry and calls `captureWorktree` to prove the identity has not changed before widening its disposable list; `reconcileLocalCleanup` then calls `inspectWorktree`, which calls `captureWorktree` again. Both `lstat` the path and throw a raw `ENOENT`, which the reconciler maps to `local-operation-failed` and the CLI to `local-cleanup-failed`. Nothing in the journal advances, so the entry stays `released` / `none` forever, and `preview` spends part of its sixty-second budget re-verifying it on every pass.

The journal already holds everything needed to finish safely: the exact path, filesystem fingerprint, head, and ref recorded at release. When the path does not exist, the identity question is moot; the only questions are whether the merge/archive evidence still says this candidate is integrated, whether Git still registers something at that path, and whether the local ref still equals the journaled head. So the reconciler adds one branch before inspection: step `none` and `exists(entry.path)` is false. It verifies evidence exactly as the removal path does, then asks Git's inventory for rows at that path. No row, or one prunable row whose `gitdir` file resolves to `<path>/.git`, is the dismantled shape #453 already handles in `retireRegistration`; a valid row is a foreign worktree and blocks with `residual-or-reused-path`. The branch then journals `state: deleting`, `step: worktree-removed`, records `worktree-already-absent`, and falls into the existing ref deletion, which already tolerates a missing path and enforces the expected old SHA. `completeLocalCleanup` skips the identity recapture when the path is absent so it can reach the reconciler; a `complete` invocation for an absent path that has no registration blocks with `worktree-absent-unregistered`, because without a journaled head there is nothing to compare the ref against.

## Merge event skew

`assertManualAcceptanceMerge` requires exactly one `merged` timeline event by the same human actor, without an App, with the same commit as `merge_commit_sha`, and with `created_at` equal to `merged_at`. GitHub writes the pull request's `merged_at` and the timeline event from different services; #449 shows `2026-09-17T08:50:20Z` on the pull request and `08:50:21Z` on the event. The equality was meant to bind the event to this merge rather than an earlier merge of the same PR; the commit and single-event checks already do that. The change parses both timestamps and requires `|event − merged_at| ≤ 5000 ms`, failing closed when either does not parse. Five seconds is far above observed skew and far below any plausible second merge. The other checks are untouched, and the fixture adds a skewed-by-one-second event that passes and a skewed-by-a-minute event that still fails.

## `.artifacts` as one disposable root

`.gitignore` ignores `/.artifacts/` as a whole; it is where every repository script and every agent writes generated output (`openspec-archive`, `validation`, `final-package`, `manual-package`, run logs, pack dry runs). The policy so far authorized only two subroots and explicitly refused the parent, so any other generated file there blocked cleanup with `worktree-content`, and the reports show three merged worktrees blocked solely on such files. Those worktrees were then deleted by hand, which produced the first failure class.

`COMPLETION_DISPOSABLE_PATHS` replaces `.artifacts/openspec-archive` and `.artifacts/validation` with `.artifacts`. The registration schema already accepts `.artifacts` (`disposablePath` in `local-cleanup-state.mjs`), so old entries that list a subroot keep validating and are widened on the next `complete` like any other entry. Inspection still requires every path under it to be ignored, inside the worktree, and free of links, special files, and nested repositories, and still counts it under the generated allowance; near matches such as `.artifacts-user` or `artifacts` remain unknown ignored content. The spec's "validation-report policy remains exact" scenario becomes "artifact root policy remains exact" with the near-match examples moved outside `.artifacts`.

## What this is measured by

After merge, `complete` for each of the five stuck entries should report `removed` with `worktree-already-absent`, `local-ref-already-absent` (their branches are gone) and the journal should hold no `released` entry for an absent path. `reconcile-openspec-archive.mjs --dry-run --pr 449` should report `accepted-and-archived`, and `complete` for #449 should remove its worktree. The next worktree that carries a stray `.artifacts/*.log` should complete in one pass.
