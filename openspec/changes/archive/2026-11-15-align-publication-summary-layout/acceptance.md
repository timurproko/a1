# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Publication and failure headings place their full-log links directly beneath them without indentation.
- The development failure heading keeps its existing prefix without a dot or extra color.
- All failure details use the same indented asterisk bullets after a blank separator.
- Colored progress dots and aligned statuses remain unchanged while diagnostic limits and npm staging truthfulness are preserved.
- Interrupted or unavailable observation retains an unindented log link without claiming a completed remote outcome.
