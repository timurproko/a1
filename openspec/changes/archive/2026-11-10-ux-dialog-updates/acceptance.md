# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Session Info opens in the input dock with the transcript and footer visible, complete scrollable report data, and prompt restoration on close.
- Sign-in method and provider selectors use accent-bold Title Case headings without trailing colons and standard background-highlighted selections.
- Project-trust dialogs use standard titles and selections, while saved and current values share a left-aligned column without a saved-decision path suffix.
- Nested authentication and other internal choice dialogs share standard title, foreground, and selected-background roles.
- Internal choice lists wrap at both ends through current search results, including providers, methods, trust, Launcher, and Settings selectors.
- Session Info identity and grouped values share a left-aligned value column at feasible widths, with complete wrapped paths and report details retained.
- Every provider login state uses the live-themed title, immediate muted description, blank-row input spacing, accent chevron, shared inset, and standard footer.
- Authentication results, safe links and device actions, trust decisions, paging, section jumps, document scrolling, and comparison presentation retain their existing behavior.
- Providers retain real configuration status with a muted separator dot, success-green configured text and trailing checkmark, without decorative preferred-partner badges.
