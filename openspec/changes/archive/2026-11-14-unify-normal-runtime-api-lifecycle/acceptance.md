# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Ordinary and compatible launches share one captured runtime identity across color control and session/worktree context.
- Normally settling Core publication contention preserves the latest ready successor without allowing an older runtime to reclaim or clear its binding.
- Inactive compatible tabs converge to their destination color through current membership and acknowledged public APIs in local and routed Core-only fixtures.
- Stale, partial, expired, moved-again and replaced targets do not authorize a different session or change peer colors, saved Default or invocation replacement policy.
- Comparison and noninteractive exclusions remain unchanged, and persistent locks or unsettled writes still fail closed without automatic ownership repair.
