# Implementation evidence

## Delivered outcomes

- Bare A1 supplies a product-owned export-storage service from composition. Implicit HTML and JSONL exports use the persistent selected user home `.a1/exports/`, not temporary development data/config or the checkout. Timestamp/session/UUID filenames are reserved exclusively with private permissions. Explicit destinations, quoted paths, format flags with explicit destinations, and comparison defaults retain their intended behavior. Failed default writes remove only the same reservation; a missing storage service fails visibly instead of silently writing into cwd.
- Optional export writers and the pinned command-changelog reader remain deferred. Startup maximums were not raised; the optional-module list now explicitly guards those modules. Partial workflow-host injection preserves class methods and their original receiver.
- Eligible cleanup preflight combines existing content checks with exact checkout-owned development-process identities. It reports all known local blockers together using paths, PIDs, start identities, and script paths, without reporting complete command lines or user file contents. Inspection failure remains distinct from an empty inventory, and budget failures retain deferred disposition.
- Only explicit exact `complete --stop-dev-processes` carries process-stop authority after merged/released eligibility and clean-content checks. It rechecks process identity before every stop, protects caller ancestry and foreign code roots, bounds settlement, reports survivors, and repeats ordinary cleanup checks before purge. Windows start identity is checked against a pinned process handle. Sweep and preview never acquire stop authority.
- Explicit confirmed `preserve-export` is bound to one named regular untracked HTML/JSONL file in a registered released eligible merged implementation checkout. It uses a private exclusive destination, bounded hashing/copying, file flush and verification, source/destination/ancestor revalidation, and durable journaling before source unlink. Verified-copy and source-unlink interruption recovery retain the same destination. Tracked content, other unknown work, links, escapes, source/destination drift, foreign ownership, and unavailable delivery evidence remain blockers. Worktree removal is still a separate ordinary cleanup operation.
- Updated session-export documentation, cleanup runbook, and agent guidance. No supervisor, job object, persistent watcher, broad process-kill rule, or generic force deletion was introduced. The previously blocked launcher worktree and its user export were not moved or deleted by this delivery.

## Focused local evidence

- The two affected cleanup regression fixtures passed 135 cases, including native Windows exclusive-handle and junction safeguards plus the new preservation and stop-authority cases.
- The final focused cleanup rerun passed 11 cases covering explicit stops, dirty/ineligible vetoes, named preservation, links, drift, recovery, non-overwrite, deferred budgets, and CLI authority confinement.
- After reconciling `origin/develop` through Pi 1.5.1, 158 tests passed across ten affected process/preflight, lifecycle export, engine export/workflow/adapter/host, composition wiring, and autocomplete files.
- The native Windows process fixture used a real private Node child and real process creation identity to demonstrate exact selection and shutdown. Windows inspection transports JSON as base64 to avoid console corruption, and reports never include the collected full command strings.
- Build, typecheck, architecture/startup, session-writer, product-identity/package, pinned source-port provenance, changed-file documentation, and strict OpenSpec checks passed. The composition factory size ratchet was lowered after extracting its cohesive host-options builder; no budget or required gate was widened.
- The complete committed-change naming audit inspected 25 files with zero violations. The additional CLI-authority and deferred-budget cases passed in the final focused cleanup rerun.
- Required exact-head CI remains the post-ready authority. Local checks and private fixtures do not claim live cleanup of another worktree, manual acceptance, or successful renewed remote validation.

## Known gaps

None. Genuine local work, active/current or unverifiable processes, permission failures, linked storage entries, and conflicting/unverified partial copies intentionally retain data rather than bypass safety. Only integrated tooling and separately confirmed candidate-scoped operations may act on live completed worktrees.
