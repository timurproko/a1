# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Both normal entry names share ordered positional prompts and preserved leading control routing.
- Session selectors preserve history, cwd and one-writer admission, including failed startup and custom-ID contention.
- Memory sessions stay fileless; ordinary tools work while durable worktree operations fail explicitly.
- Invocation model, scope, effort and provider-key overrides leave saved defaults and credentials unchanged.
- Process trust and global/CLI hooks gate project factories using actual UI availability and explicit remembering.
- Development inspection and malformed-payload diagnostics redact invocation credentials; release records contain no invocation keys.
- Unsupported retained releases and undelivered contracts fail explicitly; full Pi parity remains pending P2–P4.
