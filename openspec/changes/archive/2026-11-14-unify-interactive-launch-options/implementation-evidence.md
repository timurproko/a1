# P1 implementation evidence

## Outcome 1: shared default CLI/discovery

Code and tests are written for the shared public option normalizer/help, thin pi naming/control adapter, ordinary positional prompts, ordered startup delivery, common concrete command/catalog wiring, public/internal payload separation and selected-release refusal for ordered-message payloads. Both entries retain the normal product runtime and existing API lifecycle. The pi-named update word is maintenance; its source-less uninstall cannot remove A1. Model/storage/extension/exclusion/color/registered-flag options no longer disappear in ordinary dispatch.

Focused local results on native Windows/Git Bash, Pi 1.5.2:

- Core build and source/bin typecheck passed.
- Six targeted files passed, 255 tests: CLI shared launch/dispatch/compatible/version stats, launch interactive arguments and composition startup color.
- Four additional targeted files passed, 50 tests: actual CLI subprocess probes/catalog/packaged shim, development transport, authenticated release startup transport and real SDK/owned-UI extension lifecycle (including paired ordered-message cases).
- Architecture, session-writer/public-boundary/product/package/source-ledger checks passed via the existing architecture command.
- Strict OpenSpec and whitespace checks passed.

The former development unknown-word no-op test was updated for approved positional grammar and changed to an isolated print-environment inspection, so it does not execute a real prompt. A first pre-update run exercised its outdated assumption and timed out; a targeted process check afterwards found no matching development/UI process remaining. Its old expectation is not evidence against the approved behavior.

Existing broader lifecycle tests are retained; parser snapshots intentionally changed only for approved bare prompts, reserved failures, standalone storage and shared extension flags. New actual entry fixtures isolate profile/config/data/runtime and offline discovery. Factory marker sentinels prove help/version do not load factories; Firstmate catalog probes still refuse before marker-writing factories. These are deterministic fixture results, not live Firstmate/desktop or installed-global certification.

## Outcome 2: guarded session/model/trust

Code and tests are written for continue/resume/fork/exact ID/name/memory selection, model scopes and process-only credentials, process trust overrides and global/CLI trust hooks. Both names use the same normal-product composition and writer-owning runtime. New selector/model/trust code is conditional; the startup graph/function-size limits were preserved rather than raised. Writer governance adds only the exact optional selector owner and still requires its lock dependency.

Focused local results on native Windows/Git Bash, Pi 1.5.2:

- Core build and source/bin typecheck passed.
- Ten targeted files passed, 182 tests: shared/compatible CLI, internal argv safety, pre-resource dialogs, session selection, real runtime/session launch, project-trust ordering, authenticated release transport and writer-owner governance.
- Seven boundary files passed, 55 tests: actual executable/package discovery, both development entry names, real SDK/owned-UI lifecycle, editor-history composition, ordinary worktree tools and owner-verified recovery, plus startup color.
- Architecture, unchanged startup reachability budgets, exact guarded-owner checks, product/package identity and pinned source-ledger checks passed.

Behavioral fixtures establish:

- Continue reopens real local history, with new-session fallback. Exact IDs do not become prefix matches; concurrent creation admits one writer, and initialization failure releases both reservation and real writer. Forking a live source preserves its bytes and branches into the original invocation cwd with independent identity/authority. Existing source-cwd restoration and compacted-context tests remain active.
- A genuine memory manager remains fileless across replacement, has no resume hint and uses ordinary cwd tools without durable context lookup. Durable detach fails explicitly; automatic repository naming and both editor-history scopes are withheld. HTML rejects memory storage while explicit JSONL export succeeds without converting the running session.
- Invocation model/scope/effort/key precedence uses actual services. Keys remain provider-bound across replacement, and recursive fixture inspection finds no key in settings/auth/transcript artifacts. Saved defaults remain unchanged. Development inspections redact raw and structured credentials for both names, and malformed internal JSON diagnostics omit payloads.
- Real global and CLI factories are reused once; their trust hook precedes project factories. Actual UI capability/confirmation and explicit remembering are exercised. Process overrides bypass hooks/saved decisions without modifying trust files. Headless denial and failed handlers withhold project factories and do not repeat sensitive handler errors. Real headless development children reject resume before any marker-writing factory runs.
- New metadata survives cold and compact-warm authenticated bootstrap transport; an earlier shared-parser release lacking the selector support marker is refused before spawning. Release records contain no credential payload. The actual terminal child is intercepted in these release-admission fixtures, not represented as packaged positive session certification.

Initial focused runs found stale help/trust-order expectations and dialog readline terminal-mode behavior. Expectations now distinguish global bootstrap from project admission; canonical line dialogs restore input ownership without introducing another terminal renderer. Targeted re-runs passed. An initial architecture check also rejected eager growth; conditional ownership fixes passed without increasing budgets.

Reconciliation incorporated current develop, including row containment and paste/selection fixes. Its tighter startup budget exposed a further eager-selection cost: the existing coordinator/selected-writer map were factored together, leaving lookup/picker code conditional and storage authority with trust preflight. The same build/typecheck/architecture checks passed without a budget change. Reconciled parallel boundary checks exposed the lifecycle fixture's one-second readiness assumption; it now awaits the actual startup/delivery flush fence and keeps the capability assertion, rather than raising a timeout or weakening it. The targeted owner and boundary checks were repeated for the reconciled candidate.
