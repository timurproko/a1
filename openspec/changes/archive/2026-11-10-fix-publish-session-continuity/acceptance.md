# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Large saved conversations reach input readiness and resume with unchanged identity, history, and source bytes.
- Model selection and installed-update notices leave large-session work usable without false queue overload or repeated mutations.
- Genuine delivery pressure resumes only after cancellation and command settlement, while failed recovery still permits quit.
- Stalled live writers retain exclusive ownership, and normal disposal or failed startup releases session ownership.
- Live release claims preserve executing code, dependency layers, and certification across successor activations; later launches select the successor.
- Incident diagnostics distinguish delivery failure classes without recording private conversation or tool content.
