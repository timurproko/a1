# Conditional implementation acceptance

Verdict: accepted only when an authorized human manually merges the containing exact pull-request head after required current-head validation, or personally enables native auto-merge for that unchanged head and GitHub integrates it after the validation succeeds.

The maintainer integration decision accepts these scenarios:
- Every named choice stores only its primary accent; one reusable transform derives secondary headings, active filters, Markdown list markers, all dialog bars, and low-prominence surfaces in truecolor and 256-color terminals, and accepts future custom colors.
- Filled scope/default markers use neutral item text color rather than an accent-family color.
- Blue and magenta hue sectors receive stronger derived H2 shifts for clear title/section hierarchy.
- Keyboard-shortcut key spans and ordered/unordered Markdown markers use the same live secondary tone as active filters across all six palettes, while general Markdown code stays unchanged.
- Purple receives the same complete semantic projection as every other choice; unrelated base-theme roles remain unchanged and comparison mode stays isolated.
- The accent dropdown presents six effective-color squares while its current-value checkmark uses standard text color.
- Generic contains only Update check, and Appearance contains Accent color followed by Quit animation.
- Live selection repaints the active frame, including finalized assistant-list markers, and persists only in the selected A1 profile.
- Scrolled-out sticky prompts and jump-to-bottom controls remain neutral grey until hover applies the configured accent.
