## Why

Repeated rendering captures, broad PR ownership, repeated setup, and exhaustive pull-request matrices delay feedback and waste hosted compute. The initial implementation removed some duplicate work but retained a 502-file conservative inventory and can still schedule 24 modular jobs; the approved refinement makes ordinary pull requests cover the most critical affected behavior while deferring exhaustive permutations to Full, nightly, and release authority.

## What Changes

- Add reproducible test-cost and coverage inventory reporting against current source and existing CI evidence.
- Deduplicate full rendering/input captures while retaining smoke-only assertions.
- Narrow reviewed PR ownership subareas with conservative fallback and changed-test/shared-support protection.
- Reduce fixture initialization and independent CLI capture process overhead without sharing mutable scenario state.
- Audit remaining overlap and consolidate only equivalent checks with replacement coverage recorded.
- Remove demonstrated duplicate exact-package preparation work within existing lane authority.
- Harden orchestration and document ownership, measurable savings, and remaining bottlenecks.
- Replace owner-wide pull-request selection with bounded critical floors plus changed and transitive consumers.
- Run expensive integration, rendering, native, chaos, and platform permutations only for direct affected surfaces or exhaustive cadence.
- Cancel remaining matrix work after a decisive failure and enforce bounded pull-request compute selection.

## Capabilities

### New Capabilities

- `validation-efficiency`: Coverage-preserving test orchestration, selection refinement, fixture optimization, and auditable cost reporting.

### Modified Capabilities

- `continuous-integration`: Pull-request validation becomes a bounded critical gate while exhaustive coverage remains owned by Full, nightly, and release workflows.

## Impact

Validation scripts, ownership and integration registries, Development workflow scheduling, rendering selection, focused regression tests, and validation documentation. No product behavior, publication cadence, merge authority, retry policy, assertion deadline, release coverage, or startup budget changes; ordinary pull requests intentionally stop repeating exhaustive coverage that remains required in Full, nightly, and release workflows.
