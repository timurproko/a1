## Context

A1 embeds Pi 1.5.2 with an owned UI and independent A1 profile. Firstmate's adapter pins a real executable with type -P, supplies a positional brief and Pi options, probes help/version/catalog, and loads tracked extensions. Its native Windows identity correction is already committed in the separate Firstmate checkout and is read-only here.

## Decisions

1. Keep ordinary A1 command routing and `a1 pi` semantics. Add `bin/pi-compatible.js` and a shipped opt-in pi shim directory; retain npm's sole globally registered a1 command. Users opt into that directory only in a dedicated Firstmate launch environment; inherited PATH supplies the same executable to workers. No global pi bin registration.
2. Keep Pi knowledge in CLI/launch/Pi engine owners and composition wiring, not neutral UI contracts. Use the existing validated argv/startup payload path across immutable release/guardian boundaries; require exact selected-release support and fail closed for old consumers.
3. Identity is engine family, not product branding. Publish AI_AGENT=pi and PI_CODING_AGENT=true before extensions. Clear FM_PI_SESSION_PID/START and parent shell metadata at independent UI process entry, never when creating Firstmate's second in-process AgentSession or ordinary helpers. Firstmate alone publishes/verifies its native ownership evidence.
4. Resolve models and effort from the selected profile's real Pi catalog after explicit extensions register providers. Invocation overrides win over resumed state without rewriting saved defaults. Keep session writer coordination and project trust intact.
5. Help/version do not load extensions with factory side effects. Catalog queries may load trusted/configured and explicit extension factories but must not bind/start a session, replace live host markers, or make an LLM request. Unknown extension flags are accepted only through actual loaded registrations, otherwise rejected.
6. Keep the existing prompt byte bound unless a measured Firstmate brief proves a bounded change necessary. Preserve literal argv, Unicode, quotes and newlines; reject oversized/NUL input.

## Validation strategy

Focused typecheck, changed-owner tests, architecture checks and strict OpenSpec validation only; no broad local preflight/full/release suite. Include real public CLI failures/successes, selected-release transport, disposable packaged-entry smoke and real embedded extension lifecycle. Use only named disposable Firstmate state and exact owned test processes. Live main/worker/concurrency/steering/recovery acceptance is reported separately from deterministic tests; inability to complete it is an explicit gap, never compatibility success. No active user Firstmate state or unrelated terminals are touched.

## Risks and limits

Retained release compatibility must not mistake an old startup parser for support for new options. Extension errors must not silently produce instructionless workers. Native Codex effort flags require a loaded registering extension, not hardcoded claims. Physical terminal/Herdr acceptance requires its existing named-lab guarded procedure. No account/profile fallback, unrelated Firstmate correction, merge, landing or cleanup is authorized.

## Completed A1 lifecycle implementation

The maintainer subsequently requested completion for CI and chose to do real Firstmate testing afterward, with corrective PRs for any failures. Firstmate remains read-only; live deployment testing no longer blocks completion of the A1 implementation ledger. This supersedes the initial partial handoff, not its historical test observations.

New deterministic coverage composes the real A1 host, profile/settings, owned renderer and input bridge over real Pi AgentSessionRuntime instances and loaded extension factories. Only the external model transport is replaced, so no LLM/account calls occur. Eight scenarios cover asynchronous startup before the exact initial prompt; once-only startup digest in model context; extension status/widgets/warnings/info notices and tool renderers; nested task-copy writes while independent helpers retain operational cwd; queued follow-ups across distinct agent-start/turn-end/settled boundaries; transformed steering acknowledgement; blocking input through the actual owned editor; live shell metadata after model/effort/session changes; two independent worker compositions; durable extension-owned notification delivery across replacement; and new/reload/resume/fork ordering with a real second in-process SDK session using the selected profile's settings and authentication source.

Those tests exposed and fixed A1 races: the initial prompt and replacement withSession callback could run before extension startup completed; SDK reload plus A1 rebind could emit duplicate session_start; generation-scoped UI reset could clear new startup widgets; and startup notices could be cleared by initial prompt submission before a visible frame. Binding is now once per AgentSession with a forwarding UI target, startup is awaited on prompt admission/flush and replacement, old UI surfaces reset before new hooks, and the initial prompt paints startup surfaces first. Existing command admission/cancellation semantics remain unchanged when no owned UI is attached.

## CI repair after first finalized candidate

The first exact-head CI run found a missing .openspec.yaml in the archive, unapproved literal branded member names in new test fixtures, and the extensionless bin shim falling outside the existing naming classifier's supported shell paths. Add the normal spec-driven schema/creation metadata; use the centralized product identity for fixture keys; declare the exact bin/pi-compatible/pi entry as shell input to the existing naming inspector, retaining full shell identifier checks and rejection of other unsupported bin paths. New regressions exercise both rejection and inspection, rather than excluding the shim or adding broad language exceptions. The package/CI architecture, naming rules and existing assertions are unchanged. Existing shell UI coverage also expected SDK reload to restore bindings automatically, but its Session test double only recorded a reload call; the double now performs that documented rebind itself, keeping the existing two-bind assertion while the real SDK regression still requires one session_start per generation.

The next CI run passed finalized delivery, naming and resource-sensitive validation, then found an obsolete collaborator assumption that rebind must re-run a successful factory on the same session, plus deferred publication against stripped-down resume-hint test managers. Keep the original binding-failure assertion by making its failure occur on a replacement session; add explicit same-session forwarding and detached/obsolete completion isolation checks. Suppress completed binding views and callbacks after detachment or session replacement, and publish a current failure view only once. Resume-hint fixtures retain the original session manager's public methods while overriding persistence metadata; their existing output assertions remain unchanged.
