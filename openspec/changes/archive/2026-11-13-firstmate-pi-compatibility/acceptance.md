# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- The opt-in pi executable launches normal A1 through supported release selection without replacing global Pi or changing comparison mode.
- Literal prompts and model, provider, effort, extension, session and tool-exclusion overrides survive launch without rewriting saved defaults.
- Independent UI hosts retire inherited authority while session-aware shells expose the current model, effort and session identity.
- Initial prompts and replacement callbacks wait for extension startup, and new, resume, reload and fork each retain one startup lifecycle.
- Owned UI tools, renderers, widgets, notices and input preserve follow-up, steering and logical settlement semantics.
- Attached built-in tool writes remain isolated from independent helper working directories and other worker sessions.
- Firstmate-scoped catalog probes refuse before extension factories can replace live markers instead of returning a misleading successful response.
