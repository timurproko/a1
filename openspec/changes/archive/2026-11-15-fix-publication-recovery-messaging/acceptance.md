Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Canonical filesystem aliases start the verified recovery entry without dispatching recovery behavior on import.
- Cancellation and updater loss preserve the complete callable launcher set through aliased recovery entries.
- Development publication reports changed job states without repeated setup, teardown, or unchanged snapshots.
- Failed publication identifies the primary lane and concrete diagnostics, with full logs and truthful npm staging state.
- Interrupted waiting and unavailable status retain the run link without claiming a final remote outcome.
