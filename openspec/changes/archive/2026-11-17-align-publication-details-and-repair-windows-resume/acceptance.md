# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Every publication failure asterisk uses the same two-space indentation as job-status dots in interactive and append-only output.
- Publication headings and full-log links remain flush left, with the existing blank separator and diagnostic limits preserved.
- Packaged resumes that fail before input readiness retain available sanitized fatal classifications and owned source locations before runtime cleanup.
- Missing or unreadable fatal diagnostics preserve the original readiness failure without exposing raw crash contents.
- Independent packaged session resumes retain concurrent launches, marker isolation, and independent cleanup without wider readiness budgets.
