# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Supported bare launches use the invocation color before the first startup, trust, or editor frame without changing saved Default.
- Successful replacements retain invocation initialization while live Current edits, failed replacements, and peer sessions remain isolated.
- Core-hosted A1 publishes complete endpoint-ready session and runtime identity without App, customization, or companion setup.
- Older runtime callbacks and cleanup cannot overwrite, clear, or reclaim a newer cooperating runtime's terminal binding.
- Missing Core context, unavailable commands, bounded subprocess failures, and unverifiable ownership leave ordinary A1 usable.
- Version-1 discovery, literal prompt boundaries, no-override initialization, and comparison behavior retain conservative compatibility.
- Documentation distinguishes known-space first-frame launches from subsequent live matching for manual and new-space launches.
