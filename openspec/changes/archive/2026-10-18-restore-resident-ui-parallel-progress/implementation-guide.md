## 2. Implementation dependency graph

1. **Reproduction and observation:** isolate exact artifacts, establish the real-provider/real-renderer fixture, then classify the stalled boundary. Build negative controls before treating the observer as evidence.
2. **Native contracts:** settle transaction observation, snapshot identity, capability negotiation, geometry, and effect ownership. Include all required style fields now so the painter does not need a second incompatible rewrite.
3. **Holder commits:** implement immutable coherent snapshots, bounded transaction recovery, dirty-row retention, and reconnect-independent draining.
4. **Routing and fairness:** migrate server/attach lanes, subscriber management, lock boundaries, and blocking writers. If reproduction shows an engine dependency, repair it with its regression here or earlier; do not wait for cosmetic work.
5. **Final composition and activation:** one outer envelope, damage against completed paints, coherent view/resize commits, and first-input attribution.
6. **Fidelity and integrated evidence:** complete semantic style/effect handling, real-solo comparisons, per-platform callers, and delivery bookkeeping.

Write focused failing tests with each repair, not in a final testing phase. Tasks 1–2 are decision gates; if native transport cannot satisfy coherence or the public API cannot recover required fidelity, report the exact blocker and refine this plan with the maintainer before broad implementation. No alternative visual bridge, vendor fork/upgrade, native-host refactor, or provider-policy rewrite is implicitly authorized.

The plan does not require outcome 1 to be checked before outcome 2. Outcome 1 depends on holder/routing work; outcome 4 depends on composition/geometry work. The completion map in `tasks.md` prevents checking an outcome merely because an earlier task group ended.

## 3. Representation and protocol contract

Prefer **complete immutable row snapshots on the wire with shared unchanged rows in memory** for the first repair. Native attach computes outer damage. Do not add wire patches unless measured encoding volume still prevents the approved budgets; if patches become necessary, document explicit base identity and full-resync handling before implementing them. This avoids a patch-chain dependency in a latest-value mailbox.

The new negotiated representation must describe:

- Tab ID, authenticated holder incarnation, monotonic committed revision within that incarnation, child columns/rows, and geometry generation. Keep server epoch, controller generation, client view-request generation, and geometry generation distinct.
- All rows, including blank/trailing cells; grapheme text, width/continuation cells, style and hyperlink references; complete cursor and mode state. Row equality includes attributes, links, blank backgrounds, and width, not only text.
- Snapshot kind: normally committed or bounded recovery/provisional geometry state. A re-offer does not manufacture a new child-render observation. Equal revisions are valid idempotent re-offers, not proof of progress.
- Generation-scoped view/resize responses so a delayed A→B→A response, old holder connection, or superseded resize cannot become current. Authenticate and fence incarnation at server ingestion as well as attach consumption.

Keep named-map generation-1 changes additive. Negotiate separately across holder↔server and server↔attach; a new client greeting is not proof that an old holder supports the representation. Test new/old combinations on both links, an old retained cohort after an upgrade, reconnect, and unsupported required features. Legacy peers receive a complete legacy body, never a structured patch interpreted as ANSI; report the legacy parity limit. Do not kill/restart live tabs to upgrade them automatically.

Use the existing 2 MiB encoded frame, 1 MiB input, nesting, and collection ceilings. Specify dimension/cell/attribute/link and decoded-memory bounds before allocation, including arithmetic overflow and worst-case Unicode/link expansion. Intern repeated attributes/links where useful. An oversized snapshot must produce a bounded typed incompatibility/overrun outcome retaining the last coherent view, not silent clipping, a larger global frame limit, or a disconnected unbounded assembly buffer. If supported viewport geometry cannot fit, resolve the encoding/assembly contract at task 2 rather than discovering it at handoff. Regenerate `native/terminal-host/protocol/fixtures.json` using `examples/write_protocol_fixtures.rs` and cover Rust/TypeScript decoders, mixed-feature records, and malformed inputs.

## 4. Transaction and retained-state state machine

Maintain mutable parser state and a separately owned latest committed snapshot; this is one terminal authority with an immutable publication copy, not two renderers. Snapshot rows must not alias mutable parser memory. Dirty-row extraction must retain changed data even while transport is unsubscribed, and clear dirty flags only after it has been captured successfully.

Define idle/open/recovery publication states. A valid begin opens one non-nesting transaction; another begin cannot renew its deadline. End commits the latest complete state. Continue PTY ingestion, terminal query replies, mode observation, controller handling, and timers throughout. Test splits at every control-sequence byte, UTF-8 splits, end-only writes, multiple transactions in one read, and an end followed by another begin in the **same** read. Checking only the mode after one arbitrary `terminal.write(bytes)` misses the completed transaction in the last case. Use a proven native parser-boundary mechanism, not raw-chunk regexes or A1 text heuristics.

Start with a declared 250 ms transaction-recovery deadline, measured from the first unmatched begin, and test it with a fake clock. This is a proposed engineering value, not a measured property of the current implementation. Recovery may expose a typed recovery snapshot of valid parsed state, but must not call it a normal completed child frame. Release publication suppression locally without restarting the child, and define late-end, repeated-begin, terminal reset, resize, child exit, and next-valid-transaction behavior. Neither new bytes nor repeated subscription requests extend the deadline. Performance tuning may change this engineering constant with recorded rationale, not remove the bound or count recovery as parity success.

Apply the same committed-state rule to ordinary output, subscription, reconnect, resize, and crash/recovery surfaces. If no committed snapshot exists yet, keep the coherent prior view or bounded loading state; never substitute a half-erased parser screen. Non-synchronized output uses bounded fair coalescing, not transaction claims based on transport read boundaries.

## 5. Queue, scheduling, and ownership rules

| Lane | Retention / overload rule |
| --- | --- |
| Raw PTY bytes | Ordered, lossless bounded byte queue; never replace or drop raw chunks. Local producer pressure is not permission to block other tabs or allocate indefinitely. |
| Semantic input / paste / controller barriers | Ordered, byte-accounted reliable lane. Preserve whole-paste reservation and existing drain/nonce acknowledgement. Reject before admission or report existing uncertain-delivery semantics; never silently retry an uncertain command. |
| Latest committed visual state | At most one replaceable pending complete state per relevant destination, plus bounded in-flight state. Replacing it cannot erase control, effects, or resync identity. |
| Lifecycle / topology / status | Reliable ordering for authority changes; replaceable status only where its established sequence contract permits. Never infer controller readiness from a surface. |
| Terminal effects | Separate bounded ordered lane with foreground and incarnation/sequence attribution. No replay on subscription or deduplication by surface revision. |
| Diagnostics | Opt-in bounded content-free records; drop/count diagnostic overflow without blocking the product path. |

Document capacities, byte ownership (queued **and in flight**), high-water marks, overrun behavior, wake ownership, and teardown for each producer/consumer. Preserve existing server control bounds of 1,024 frames / 4 MiB and the 1 MiB holder input admission contract unless the measured repair requires an explicitly justified change. Start fairness experiments with at most 8 events or 64 KiB or 2 ms per class per round, whichever is reached first; use small parser slices so a single giant item does not defeat the time quantum. These are engineering starting points, not a substitute for measured latency budgets. Service due input, control, output, and animation work each round and arm the earliest remaining deadline. Keep wakeups level-safe when a producer replaces state while the consumer clears its wake flag.

A slow server writer, slow attach socket writer, or blocked outer stdout must not pin the shared server lock or the attach input loop. Reuse bounded writer ownership where possible; if physical output moves to a writer thread, it exclusively owns outer mode writes/restoration and acknowledges **completed** paints. Diff against that acknowledged baseline, or have the writer derive damage from its own baseline; never advance painted state merely because a frame was enqueued. A partial-write failure invalidates the baseline and follows existing terminal restoration/exit behavior, not a successful-paint acknowledgement. Test disconnect and shutdown while blocked so a worker or pending mode restoration is not leaked.

Track subscriber sets per tab: removing one client must not unsubscribe another client viewing the same tab. Metadata/heartbeat/recovery continue with zero subscribers; a new subscriber requests one fresh committed snapshot and later live updates. Old cache re-offers are explicitly stale. Bound stale-wait from the request start, not each re-offer. Use routing identity tokens when encoding outside the mutex so a switch/close/restart during serialization cannot resurrect old state.

Reconnect is its own bounded state machine/worker: no synchronous retry loop may pause holder parsing. Keep one pending latest snapshot for the replacement peer, preserve current controller fencing, discard obsolete connection completions, and clean up abandoned reader/writer tasks.

## 6. Composition, geometry, and terminal semantics

Compute the **composite** desired screen from retained child rows plus strip and overlays, then compare against the actual completed paint. This avoids repainting cells hidden by an unchanged overlay or restoring an overlay from an old body. Initial presentation, invalidated geometry/base, and explicit resync may paint fully; ordinary equal-size updates may not. A one-row edit may repaint that row; span optimization is optional after row correctness. Mode/cursor-only updates remain observable even when no text row is dirty. Suppress equivalent no-op frames.

Only final attach composition emits DEC 2026 begin/end. Include cursor shape/blink, visibility, row damage, overlay removal, style/link resets, and final cursor before the outer end. Do not blindly forward child alternate-screen, mouse, paste, or keyboard toggles: attach owns outer input modes; holder encodes semantic input against child modes. Explicitly distinguish child-model state, attach-owned outer modes, replayable visual state, and foreground one-shot effects. Test capability fallback when the outer terminal ignores DEC 2026 without claiming physical atomicity for that terminal.

Track columns/rows and geometry generation through resize. Holder parser resize is not a child-render acknowledgement; the pinned Ghostty API even clears sync mode on resize. Preserve a safely fitted/clipped prior coherent screen as provisional until the replacement is ready. Define clipping for wide-cell tails, overlay bounds, and final cursor; do not reflow arbitrary old-width ANSI. A child resize/repaint must wake publication even if no next model token arrives. Cover A→B→A switches, old-incarnation frames, shrink→grow at equal final dimensions, rapid superseding requests, and two viewers with different dimensions. Preserve existing controller-owned child geometry; a read-only viewer fits that geometry rather than repeatedly resizing the same child for each spectator.

Keep early input attributed to the requested target and existing controller generation, not whichever body is still visible. A bounded handoff may queue admitted input; cancellation, failed target, or supersession must not deliver it to a survivor or replay it twice. Exercise first key, paste, focus and mouse after switching, Settings activation, and two-terminal control transfer.

Preserve default/indexed/RGB color semantics, intensity, underline kind/color, italic, inverse, conceal, strike, overline, supported blink, hyperlinks, and grapheme widths. Include palette/default-color changes with unchanged cell text, styled blanks, trailing erasure, combining/wide/emoji transitions, and bottom-right wrap behavior. Close OSC 8 before strip/overlay output so a child's link cannot leak into host chrome. Investigate the pinned grid-reference/formatter APIs for URI and explicit link IDs; no private structure access or vendored patch is authorized by this plan. Missing public capability is a decision-gate blocker, not a passing field.

Define an effect sequence independent of visual revision, scoped to authenticated incarnation and foreground/view generation. Two clipboard writes in one visual revision are two effects; an obsolete connection or hidden tab has no foreground authority. Dropped visual states do not drop admitted foreground effects or replay historical ones on reattach. Test synthetic OSC 52 capture without touching the real clipboard. Do not introduce durable exactly-once clipboard replay across crashes.

## 7. Real-A1 fixture and trustworthy measurements

Use the real configured engine, owned shell, transcript renderer, and native roles. Prefer a loopback deterministic streaming provider through the normal supported provider configuration; do not stub `AgentSessionRuntime` and claim engine progress. Model/tool content is synthetic, bounded, and file operations stay within the fixture root. Disable unrelated network work such as auto-naming unless it is explicitly routed to the fixture. Use isolated profile/data/runtime/session directories, synthetic credentials, and explicit release/native artifact identities; never auto-discover a user's running cohort. Keep observations off PTY stdout and off the visual protocol. A test-only metadata observer is not permission for a runtime frame bridge or private renderer interception.

Use all six first-response permutations crossed with three initial viewed tabs for the base concurrent workload. Give startup, each scenario, turn settlement, and teardown independent hard deadlines; a completion barrier must fail and release fixture-owned processes rather than wait forever when an observation never arrives. Keep all three turns unfinished behind a fixture completion barrier until each has successive engine, renderer, and holder checkpoints; for each selected interval require at least three increasing partial states and two animation transitions. Pace steps so these checkpoints are observable; production coalescing is still allowed to skip intermediate frames. Run named bounded variants for detached/no-viewer intervals, high-rate output, slow socket reader, slow outer terminal, lifecycle delay, server reconnect, overlays, two clients, and rapid resize. Do not multiply every pressure variant by every permutation unnecessarily.

Use the same scripted content in direct solo and resident at equal **child** geometry (resident outer rows include the extra strip row), color/hyperlink capabilities, theme, and runtime settings. Compare normalized child cells, cursor and attribute semantics at causal checkpoints; exclude only declared host chrome and nondeterministic clocks. Do not compare raw ANSI equality, strip whitespace/styles to force a match, or force `renderNow` to make liveness pass. Capture every emitted outer frame/transaction for intermediate coherence checks as well as checkpoint comparisons; final-screen equality cannot detect a flash. A headless screen oracle plus explicit protocol/effect assertions may be needed because no one oracle necessarily models every attribute or DEC mode.

Observations carry run/tab/incarnation, event/commit/view/geometry sequence where applicable, stage, counts, byte totals, and timestamps. A renderer progress sample records an actual completed render/write, not merely `requestRender`; a presentation sample records a completed outer write, not attach receipt. PTY ingestion is not engine progress. Do not subtract process-relative Rust `Instant` or arbitrary `performance.now()` origins across processes. Use a verified common monotonic clock or calibrated offsets with explicit error bounds, retaining locally measured segments. Fault-test clock offset, missing/duplicate/reordered observations, stale revisions, and trace overflow; invalid samples fail instrumentation rather than disappearing from the denominator.

Retain p95 targets: input-to-process 16 ms, committed-output-to-present 33 ms, retained activation paint 300 ms, and first accepted input after activation 400 ms. Separately record provider/engine-to-render, renderer-to-holder, attach receipt-to-write, per-tab worst gap, animation gap, queue high-water, rows/cells/bytes painted, and full-resync reasons. Collect at least 40 matched samples per tab for each reported steady-state percentile; use explicit counts for activation cases. Start input and activation clocks at the outer event, not after controller handoff. No missing selected frame, frozen tab, or invalid sample may disappear into a pooled percentile. For a continuously paced fixture, use a separate 1 s maximum no-progress deadline per expected stage (excluding declared provider/tool waits); this catches complete freezes independently of the tighter p95 budgets.

Negative controls deliberately freeze one engine, suppress one child render, hold one holder commit, drop one selected frame, duplicate an effect, repaint unchanged rows, and delay only one tab. Each must fail the intended assertion even if the other two tabs and final text succeed. Synthetic component faults do not establish a live root cause; record the real reproduction and its boundary separately.
