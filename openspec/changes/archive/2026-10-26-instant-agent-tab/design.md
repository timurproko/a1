# Design

## Context

`core/attach/machine.rs` sends `Request::Create` and sets `pending_created_activation`; the server replies `tab.created` only after standby promotion or `start_holder`. The attach client then requests the new view, and `roles/presentation.rs` parks blank surfaces until a first drawn frame or the bounded fallback. The existing spec explicitly keeps the old view until that frame. This avoids a blank flash but makes click-to-visible-tab depend on asynchronous process startup.

## Goals / Non-Goals

**Goals:** Paint exactly one new Agent chip and a complete idle Agent shell (empty transcript, ruled editor with a visual block caret, cwd and status footer) on the input event; transition once to the real complete surface, without input leaking to the previous tab or showing loading text. The actual child cursor stays hidden until ownership transfers. Keep launch errors and no-draw fallback recoverable and retain the existing menu/shortcut behavior.

**Non-Goals:** Make agent initialization itself synchronous or instantaneous; alter Settings/Changelog prewarming, ordinary existing-tab switches, the pinned Pi profile, or durable registry/session identity.

## Decisions

1. Represent one locally pending Agent presentation in the attach client from the accepted create gesture, before sending the server request. Paint one provisional chip with a plain shell on the same frame: a blank transcript, ruled prompt with an inverse-space visual caret, and the two-row footer. Use a cached complete Agent footer as a display-only model/context template when available, reset usage and cost to the new tab's initial values, and use neutral baseline values when none has been observed. Do not present stale usage or model data as authoritative, startup text, wordmark, child cursor, old transcript, spinner, or a clear-only intermediate frame. Render with the attach client's existing palette and canvas and crop gracefully at narrow/small dimensions. The empty editor is visual only: typing remains deferred until the real child is ready. This is a presentation intent, not a registered tab or a second agent process. A locally generated key must not be used as an authoritative tab ID.
2. Route keys and paste typed during this state into the existing deferred-created target. Do not forward body mouse/focus events to the previously viewed child while the pending presentation owns the screen. Continue to ignore repeated new-Agent actions until the requested tab has become visible or creation has failed; allow normal cancellation/view changes without hijacking a later choice.
3. Snapshot the registered tab IDs when the user creates the Agent. While its provisional chip owns the view, suppress any new Agent registry chip that appears before the create acknowledgement, as well as the confirmed target after acknowledgement; never suppress pre-existing chips. On `tab.created`, bind the pending intent to the real ID and retain the first-drawn-frame/timeout gate. Replace the provisional chip and shell atomically with the real chip and first complete child frame on commit, without one frame showing two chips. A failed create restores the prior view (or landing) with one actionable notice and discards buffered created-target input. Consider early registry lists, late surfaces, client detach, and server failure explicitly.
4. Keep provisional presentation local rather than eagerly inserting an unconfirmed registry record on the server. This makes process-launch latency irrelevant to the first visual response and avoids durable ghost tabs when creation fails. Do not solve the symptom solely by shortening `FIRST_DRAW_WAIT` or prewarming more Agent processes: neither guarantees immediate feedback and both change resource or visual semantics.
5. Add deterministic presentation tests covering the immediate plain editor/footer (including a fake caret and the model/usage footer but without a child cursor or loading text) and exactly one chip when registry updates arrive before `tab.created`, after acknowledgement, and at commit; retain role-level coverage for first paint before server response, failure, burst creation, deferred input, landing and existing-tab origins, pointer activity, and no-draw fallback. Avoid wall-clock timing assertions; assert that the first event produces visible pending state without waiting for an asynchronous response.

6. Treat a close command or pending-chip context-menu close as cancellation of this creation, never as a close of the previously viewed tab. Immediately restore that view or landing and discard the pending input. Identify the request across client/server messages so a late `tab.created` cannot activate or close a subsequent Agent. If the server has not registered a tab, abandon the start; if it already registered or launched a holder, request its normal shutdown and clear its tab rather than leaving an unseen process. Continue to permit ordinary close once the real Agent is visible.
7. Repair the finalized delivery's missing `.openspec.yaml` artifact and the failed CI documentation/architecture gates in the same PR. Split long state-machine/presentation functions without changing their behavior; keep the protocol and cancellation checks covered by targeted tests.
8. After a last-tab close, ignore late selection acknowledgements for that closed ID and never re-adopt its unlisted surface as a new initial view; keep the landing attached and able to open another Agent. Assert this in a role-level close/reopen test.
9. Tint the provisional selected chip from its configured accent with one consistent lighter initializing shade, then render the real chip with its normal active shade. Apply the same projection to all six supported accents (including the default purple), with per-accent rendering assertions; do not invent a blue-only state or change the real child theme.
10. Replace the bespoke provisional footer layout with the latest complete Agent footer presentation when one exists: keep its status-row gutters and model/context presentation but reset new-tab usage. The new tab's path row is derived from its own launch cwd rather than replaying the previous tab's branch/PR; once the real Agent resolves its repository metadata, the owned footer supplies branch and PR together. Use the owned UI's footer layout contract for the cold fallback, so missing model/metadata stays neutral without making up stale values. The first real frame replaces the preview body immediately while the preview footer stays through truecolor chip fill. Add native and owned-shell parity assertions for different widths and styles.
11. The maintainer's opt-in interactive trace captured two ordinary Alt+A/Alt+W cycles: the second close reached the registered tab (`effect=close`, `effect=cancel-view`), then the server sent `detach`. A stopping Agent can retain its bridge attachment and still ask its former controlling client to detach before the registry/view handoff completes. Reject controller-bound bridge requests whenever the registry no longer desires that Agent to run; keep the older Agent and the attach intact. `./scripts/dev` runs the production tabs CLI and only stops checkout processes *after* that CLI exits. The maintainer manually confirmed the close now keeps A1 open.
12. Animate only the selected chip's background on first real-frame commit: keep the pending light accent until commit, then fill the real chip left-to-right into its configured selected shade over a short, monotonic interval. The real body and chip identity appear together on the first frame, never fade or delay behind animation. Draw whole display graphemes, preserve cell width, click geometry, glyph/title foreground styling, overflow and narrow strips; snap to the solid selected chip if truecolor is unavailable. Cancel the animation on close, switch, or a new create and settle exactly at its deadline. Deterministic strip frames and attach-level handoff/close tests guard the transition.
13. Remove the landing wordmark's middle-row left full block so the `a` has no protruding stem. Preserve the accent, overall wordmark placement, and the Agent preview's visual caret; decision 16 restores an in-bounds left stroke and aligns the landing footer rows.
14. During the real chip's bounded truecolor fill, keep painting the exact provisional footer rows already shown, including the new tab's plain cwd path and cached status model/context or the neutral fallback, over each complete real Agent frame. Render the latest real body/editor immediately and leave input ownership unchanged; only the footer display is held. On fill completion, discard the held footer and repaint the current real structured surface once so intermediate Agent status frames never flash. Cancel the hold on close, explicit switch, or resize. Palette mode has no fill and shows the real footer immediately. Preserve child row mapping at either strip position and avoid transient cursor or hyperlink artifacts.
15. Avoid the three-step path flicker observed in the maintainer's screenshots (old tab's branch/PR → bare cwd → new tab's branch/PR). Render the pending/held path only from the requested Agent's cwd with the same one-cell left gutter and dim styling as the committed footer; retain the cached right-hand status row, never its old path metadata or link. At chip-fill completion the owned real path either stays bare (unresolved) or shows the resolved branch and PR in the same view update; the repository refresh already commits both values atomically after the PR probe. Do not delay editor, input or body on Git/PR I/O; cover cached hyperlink and cold/narrow paths in native and role tests.
16. Give the landing `a` a visible left middle stroke *inside* its existing silhouette (replace its middle row's first horizontal cell rather than reintroducing a full cell outside the wordmark). Indent the landing cwd and version rows by one cell to match the Agent footer's gutter, clipping both rows in narrow terminals and keeping the wordmark, row placement, and color unchanged. Assert exact cells and footer column parity in focused native tests.
17. Match the maintainer-approved reference (option 1): replace the middle wordmark row's blank at column zero with the lower-half `▄`, not the protruding full `█`. The lower half makes a short left descender under the middle bar while its upper half stays empty. Leave the other eight columns, upper/lower wordmark rows, `1`, accent, sizing, canvas, footer alignment, and Agent preview alone. Assert the exact three half-block rows, the blank upper half at column zero, and the descender in a focused native landing test.

## Risks / Trade-offs

- The user sees a non-interactive complete-shell approximation until the real UI draws. The preview's cached model/context can differ if the new session selects other settings; status remains display-only and is replaced by the first authoritative Agent frame. Without a prior Agent frame, the footer uses neutral `no-model` and zero-context values rather than claiming a configured model.
- Premature forwarding to the old child could leak a prompt; pending presentation and deferred target ownership must remain aligned.
- An early registry list can precede `tab.created` and expose a second chip; keep an immutable pre-create ID snapshot so the provisional and new registry chip never render together, while committed topology remains authoritative.
- If the server refuses or the child never draws, recover the old view or bounded fallback without a stuck provisional screen. A cancellation racing with holder promotion may launch the holder briefly; it must then be stopped without exposing its chip or sending its buffered input. When cancellation leaves no Agent tabs, the attach client must remain alive on its landing rather than treating the empty tab list or a cancelled create response as detach.
- Cell-by-cell chip recoloring must not split ANSI controls, wide graphemes, or a selected rename. Only the background transitions; when the selected tab changes, no old chip may keep an active-looking animation.
- Holding only footer rows must not defer child body/editor updates or redirect input. Capture the display-only preview before the first real footer changes, render it in the child's row coordinates at either strip edge, and fall back to the real footer if a complete structured body is unavailable.
- The new Agent may never resolve branch or PR metadata (no repo, offline PR lookup, or probe failure). Its bare cwd remains valid; no guessed branch or artificial wait is introduced. The cached previous tab's status may be a display-only hint, but its path and hyperlink must never be shown for the new Agent.
- Full blocks at the far left made the `a` look like it had a stray stem; no left-edge glyph made it look like a `3`. The approved lower-half-only descender resolves both while preserving the three-row footprint and the user-approved cwd/version gutter.

## Migration Plan

No persisted-data migration. Rollback removes only the client-side pending presentation, leaving the existing server create and first-draw behavior intact.
