## Diagnostic design

Add an explicit workflow-dispatch diagnostic route to Development validation, selecting one existing version and a Windows runner. It reads exact npm metadata and runs the same published smoke, never stages, promotes, rebuilds, or republishes packages. Ordinary validation routing is unchanged when diagnostic input is absent. ## Implementation observations

The repaired harness detects an authenticated crash through a bounded read-only process probe without killing only its command shell. It captures the failed attempt and transaction records before fixture-wide settlement, creates a fresh runner only after settlement succeeds, and verifies the recovery installer's exact transcript, package version, active release, version command, and help launcher. Unknown bytes, generic timeouts, cancellation, bad authority, failed settlement, failed installer, wrong manifest, inactive target, and bad launchers all remain failures. Recovery evidence explicitly keeps updateVerified=false and installerRecoveryVerified=true.

Local exact-registry reproduction used unchanged public 1307 and staged 1320 with a real non-delete-sharing Windows owner-file handle. The original worker failed with EBUSY unlink; the new harness recognized it, settled all fixture writers, completed the published installer in about 21 seconds, and verified active 1320 and both launch checks. It retained the original crash digest, failed child, process inventory, and pre-recovery journal instead of relabeling the direct attempt as success.

A recovered installation can still contain an active ownership-released journal. The candidate updater now validates the exact active installed target, canonical package and capsule authority, complete target launchers, and both recorded owner PIDs before durably settling that abandoned journal under its ordinary execution lease. It does not restart the old capsule. A real-filesystem updater test covers the complete up-to-date path; six negative cases retain active journals for live owners or mismatched/unavailable authority. Commit truth is recorded in memory before journal persistence, preserving the existing no-rollback-after-activation rule.

Targeted local validation: 150 release/recovery/compatibility tests pass, with five platform-specific skips; both typechecks, architecture, product-identity, and code-documentation checks pass. Separate focused smoke/observer/process tests cover phase output, five-minute deadline, exception recording, redaction, and identity-pinned settlement. Native Windows coverage holds a real sharing lock over the candidate worker heartbeat and requires continued ownership and a successful npm result, not merely a mocked retry.
