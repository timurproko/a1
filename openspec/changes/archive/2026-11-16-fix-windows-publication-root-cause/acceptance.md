# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Authenticated legacy heartbeat crashes recover through the exact published installer only after fixture writers settle.
- Failed direct updates remain explicit in evidence and are never reported as successful direct replacements.
- Unknown workers, cancellation, unrelated failures, and failed recovery continue to block promotion.
- Recovery preserves settings and data and requires the exact candidate manifest, active release, and callable launchers.
- Current recovery workers survive native Windows heartbeat sharing failures and still settle npm.
- A verified installer-activated target settles an abandoned journal without restarting a dead legacy owner or ignoring a live owner.
- Predecessor update waits end within five minutes and display their phase before waiting.
- Existing published pairs can be diagnosed without publishing packages or moving public tags.
