# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- The Windows published-predecessor update command receives a twenty-minute deadline, longer than the updater's fifteen-minute worker deadline; Linux, macOS, and every other stage keep ten minutes.
- A stalled or failed smoke stage writes the fixture-owned processes that were alive before settlement, with sanitized arguments, or the inventory error when inspection fails.
- Failure evidence includes bounded sanitized tails of the fixture update journal and recovery-capsule owner, result, cancellation, and start-lease records with size and modification time, and omits capsule manifests.
- Failure evidence lists the newest fixture npm logs by name, size, and modification time beside the existing log tails.
- Success and failure evidence record per-stage command durations.
- Redaction removes credential-like environment values of at least eight characters and leaves shorter ordinary words such as root readable.
