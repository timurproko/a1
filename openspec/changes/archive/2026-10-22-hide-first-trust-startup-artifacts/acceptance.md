# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- After a project-trust choice, the blank resident startup handoff shows neither a tab lifecycle glyph nor a body cursor.
- The first drawn owned-shell frame restores normal cursor and status presentation.
- Working, input-needed, settlement, restoration, restart, crash, and failure indicators remain unchanged outside that handoff.
- Pending, successful, and failed tool blocks retain one continuous background through every available content cell, including short and internally styled rows, while the scrollbar remains a separate overlay on the reserved rail.
- A moved, relabeled, or removed jump-to-bottom control or live-status row leaves exactly the newest content in the frame, with no stale second copy near the dock.
- At matching child geometry, resident capture and replay preserve solo-mode cells, styles, links, palette colors, and cursor placement through scrolling, fragmented output, resizing, and tab reselection.
- Fullscreen prompt annotations cannot insert extra lines, so content and dock rows remain aligned without stale bottom controls.
- Scrollbar track and thumb cells stay in one gutter column through the last content row, preserving the top gap and shell-owned dock spacing.
- Each tab chip starts with one space and separates its status icon from the name with one space.
- Resident fullscreen painting disables automatic line wrapping for its fixed grid and restores normal shell wrapping on exit.
